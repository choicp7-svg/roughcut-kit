# script-roughcut — 대본 기준 러프컷 (프리미어 XML · 캡컷)

촬영본 폴더와 대본을 받아, 대본 순서대로 컷을 고른 타임라인을 만든다. 컷 선택은 사람이 하듯 판단해서
`edl.json`(컷 목록)에 적고, 나머지는 스크립트가 한다. 아래에서 `S` 는 `python3 "${CLAUDE_SKILL_DIR}/scripts/..."`.

결과물은 모두 `<촬영본 폴더>/rough_cut/` 에 둔다.

## 1. 준비

- 대본 읽기: PDF 는 Read 로 열고, 안 열리면(poppler 없음) `pypdf` 로 텍스트를 뽑는다.
  대사 줄(`인물 : 대사`)과 지문을 구분하고, 씬(`#장소`) 순서를 정리한다.
- 전사: `S/transcribe.py <촬영본 폴더> --lang ko` → `rough_cut/by_clip.txt` (클립별 대사와 시각, 초 단위).
  20분 분량이면 CPU 로 10~20분 걸리니 백그라운드로 돌린다. 캐시(`by_clip.json`)가 있어 다시 돌리면 빠르다.
- 화면: `S/sheets.py clips <촬영본 폴더>` → `rough_cut/_sheets/clips_N.jpg`. Read 로 열어 클립마다
  **어느 씬·어느 앵글·누가 찍혔는지** 파악한다. 대사 없는 컷(인서트, 리액션, 동작)은 화면으로만 알 수 있다.

## 2. 컷 목록(edl.json) 쓰기

`rough_cut/edl.json`:

```json
{
 "name": "misin_script_cut",
 "cuts": [
  {"scene": "#1 선무방"},
  {"clip": "A19997.MP4", "in": 4.9, "out": 12.4, "text": "다녀왔습니다~ / 어 아들 왔어?"},
  {"clip": "A19998.MP4", "in": 8.45, "out": 9.6, "text": "여기 제 방인데요?"}
 ]
}
```

- `name`: 시퀀스·캡컷 프로젝트 이름. **영문**으로 (파일 이름이 된다).
- `in`/`out`: 그 클립 안에서의 초. `text`: 자막(없으면 빈 문자열). `{"scene": ...}` 은 프리미어 마커가 된다.
- `source_dir` 를 넣으면 그 폴더를, 없으면 `rough_cut` 의 상위 폴더를 원본 폴더로 쓴다.

고르는 규칙:

- **대본 순서**로 배열한다. 촬영 순서(파일 번호)는 무시한다. 카메라 번호는 9999 다음 0001 로 넘어갈 수 있다.
- 대사마다 **말하는 사람이 잡힌 앵글**(단독샷)을 고른다. 투샷·마스터는 씬 시작, 동작이 큰 부분, 선물 건네기처럼 둘이 같이 보여야 할 때.
- 같은 앵글을 여러 번 찍었으면 **마지막 테이크**를 쓴다 (대사가 끝까지 간 것 중에서). 한 클립 안에 테이크가 둘 들어 있기도 하다.
- 슬레이트·스태프 목소리("액션", "돌았어요", "갈게요", "다시 할게요", "OK")는 넣지 않는다. 그 직후부터가 연기다.
- 전사 시각은 앞뒤로 0.1~0.3초 어긋날 수 있다. 대사 앞 0.2초, 뒤 0.3초쯤 여유를 두고, 리액션·동작은 더 길게.
- 대사 없는 장면(먹방, 새벽, 인서트)은 화면 시트를 보고 구간을 잡는다. 길면 일단 넉넉히 넣고 사용자에게 줄일 곳이라고 알린다.
- 대본과 실제 촬영이 다르면(소품 변경, 대사 애드립, 씬 합침) **촬영된 대로** 따르고 자막도 실제 대사에 맞춘다.
- 대본에 있는데 촬영본에 없는 씬, 용도를 모르는 클립, 대본에 없는 클립은 지어내지 말고 **보고에 적는다**.

## 3. 확인 → 생성

1. `S/sheets.py cuts rough_cut/edl.json` → `rough_cut/_sheets/cuts_N.jpg` (컷마다 시작·중간·끝 프레임).
   Read 로 열어 컷마다 의도한 인물·앵글인지 본다. 틀린 컷은 edl.json 을 고치고 다시 확인.
2. `S/build.py rough_cut/edl.json` → `rough_cut/<name>.xml` + `<name>.srt` (프리미어).
3. 캡컷도 원하면 캡컷을 **종료한 상태에서** `S/build.py rough_cut/edl.json --capcut`.
   → `<캡컷 프로젝트 폴더>/<name>/`. 같은 이름이 있으면 멈춘다 — 사용자가 이미 열어 본
   프로젝트일 수 있으니 `name` 을 바꾸는 쪽을 먼저 택하고, 덮어써도 된다고 할 때만 `--overwrite`.

프리미어와 캡컷은 같은 프레임 번호에서 잘린다(원본 fps 기준, 캡컷 프로젝트도 원본 fps 로 만든다).

## 4. 사용자에게 알릴 것

- 프리미어에서 여는 법: **프로젝트를 먼저 열거나 만든 뒤**(새 프로젝트의 "가져오기" 화면에서는 아무것도 고르지
  말고 만들기), Finder 에서 XML 을 **프로젝트 패널로 끌어다 놓는다**. 그 뒤 생긴 시퀀스를 더블클릭.
  새 프로젝트 "가져오기" 화면은 XML 을 보여주지도 받지도 않는다 — "아무것도 안 생긴다"의 원인은 이것이었다.
- 자막은 프리미어 캡션에서 SRT 를 가져온다.
- 원본 영상 폴더를 옮기거나 이름을 바꾸면 XML·캡컷 프로젝트 모두 미디어가 끊긴다. 옮겼으면 build.py 를 다시 돌린다.
- 대본과 달라진 점, 빠진 씬, 통째로 넣어서 줄여야 할 구간, 쓰지 않은 대체 테이크 목록.
- 프리미어·캡컷에서 실제로 열어 보는 확인은 여기서 못 한다. 열어 본 결과를 알려 달라고 한다.

## 환경 메모

- `ffprobe` 없이 동작한다. 스크립트는 `ffmpeg -i` 출력을 읽는다(ffmpeg 가 없으면 `pip install imageio-ffmpeg`).
- 전사는 faster-whisper `large-v3-turbo` (처음 실행 때 내려받는다). 다른 모델은 `--model` 또는 `FW_MODEL`.
- 캡컷 프로젝트 폴더는 자동으로 찾는다(환경변수 `CAPCUT_DRAFT_ROOT` 가 있으면 그것, 없으면 OS 기본 위치). build.py 는 그 폴더의 가장
  최근 실제 프로젝트를 형식 견본으로 쓴다. 다른 위치면 `--capcut-root`, 견본 지정은 `--capcut-template`.
- 캡컷 자막은 캡컷이 프로젝트를 저장할 때 빠진 적이 있다(원인 미확인). 자막이 안 보인다고 하면 SRT 를 캡컷에서
  가져오게 안내하고 원인을 살핀다.
- 캡컷 프로젝트 형식은 비공개라 버전이 바뀌면 깨질 수 있다. `scripts/capcut_kit.py`, `env.py` 는 capcut-roughcut 스킬에서 복사한 것.
